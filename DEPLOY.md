# Публикация: GitHub → Vercel → домен

Пошагово. Шаги, где нужен твой аккаунт и пароль, помечены **[ты]** —
их не может сделать за тебя никто, кроме тебя.

---

## 1. Залить в GitHub **[ты]**

В архиве уже есть готовый git-репозиторий с историей — заново ничего
инициализировать не нужно, только отправить на GitHub.

### Вариант А: GitHub Desktop (без терминала)

1. Скачать GitHub Desktop, войти в свой аккаунт.
2. **File → Add Local Repository** → выбрать распакованную папку `azim-dev`.
3. Нажать **Publish repository**, снять галочку «Keep this code private»,
   если хочешь публичный, и опубликовать.

### Вариант Б: терминал

```bash
cd ~/Downloads/azim-dev

# если gh ещё не стоит
brew install gh
gh auth login          # выбрать GitHub.com → HTTPS → Login with a web browser

gh repo create azim-dev-uz --public --source=. --push
```

Без `gh` — создать пустой репозиторий на github.com/new (без README,
без .gitignore, без лицензии), затем:

```bash
cd ~/Downloads/azim-dev
git remote add origin https://github.com/ТВОЙ_ЛОГИН/azim-dev-uz.git
git push -u origin main
```

## 2. База данных

1. **[ты]** Зарегистрироваться на neon.com, создать проект (регион
   ближе к Европе — Frankfurt).
2. В разделе **Connection string** выбрать вариант **Pooled connection**
   — в имени хоста будет `-pooler`. Это важно: без пулера
   serverless-функции быстро упрутся в лимит соединений.
3. Строку скопировать — она понадобится на следующем шаге.
   Никому её не показывай, это пароль от базы.

---

## 3. Vercel

1. **[ты]** Войти на vercel.com через GitHub и разрешить доступ
   к репозиторию.
2. **Add New → Project → Import** нужный репозиторий.
3. Framework Preset: **Other**. Build Command и Output Directory
   не трогать — всё уже описано в `vercel.json`.
4. Открыть **Environment Variables** и добавить две:

   | Имя | Значение |
   |---|---|
   | `DATABASE_URL` | строка подключения из Neon (с `-pooler`) |
   | `SESSION_SECRET` | 64 случайных символа, см. ниже |

   Секрет сгенерировать:

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

5. **Deploy**.

---

## 4. Наполнить базу

Таблицы и стартовые данные появляются сами: `buildCommand` в
`vercel.json` запускает `db/bootstrap.mjs` на каждой сборке. Он
применяет схему и переносит 11 работ, 7 вкладок и 6 тэгов — но только
если таблица работ пуста, чтобы не затирать правки из админки.

Руками остаётся одно — завести вход в админку. Строку подключения
для этого не нужно ниоткуда копировать, её отдаст сам Vercel:

```bash
cd ~/Downloads/azim-dev
npm install

npx vercel link            # выбрать существующий проект azim-dev-uz
npx vercel env pull .env   # запишет DATABASE_URL и SESSION_SECRET в .env

npm run db:admin -- azim   # спросит пароль, в базу уйдёт только хэш
```

Пароль — не меньше 10 символов. Забытый пароль не восстанавливают,
а задают заново этой же командой.

Если Vercel CLI ставить не хочется, есть путь без него: команда
`node db/admin-sql.mjs azim` спросит пароль и напечатает готовый
`INSERT` — его нужно вставить в SQL-редактор базы (Vercel → Storage →
azim-dev-uz-db → Open in Neon → SQL Editor). К базе эта команда не
подключается, пароль никуда не уходит.

После этого сайт на адресе вида `azim-dev-uz.vercel.app` уже работает,
админка — на `/admin/`.

---

## 5. Домен

1. В Vercel: **Settings → Domains → Add** → `azim-dev.uz`, добавить
   заодно `www.azim-dev.uz`.
2. Vercel покажет, какие записи нужны. Обычно:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | @ | `76.76.21.21` |
   | CNAME | www | `cname.vercel-dns.com` |

   **Точные значения бери из интерфейса Vercel**, а не отсюда — они
   иногда меняются.
3. **[ты]** Прописать эти записи там, где куплен домен. Старую A-запись,
   которая ведёт на `31.184.242.14`, заменить.
4. Подождать обновления DNS (от нескольких минут до пары часов).
   Сертификат Vercel выпустит сам.

## 6. Проверить перед отключением старого хостинга

- [ ] `azim-dev.uz` открывается и показывает работы
- [ ] `/uz/` и `/en/` открываются, переключатель языка работает
- [ ] `/admin/` пускает по логину и паролю
- [ ] добавление работы через админку появляется на сайте
- [ ] `https://` без предупреждений браузера
- [ ] старые адреса `azim-dev.uz/index.php` перекидывают на главную

Только после этого отказываться от хостинга на ns8.sayt.uz. Пока
домен не переехал полностью, старый сайт — твоя страховка.

## Что осталось необязательного

**Хранилище картинок.** Vercel → Storage → Create → Blob, привязать
к проекту. Появится переменная `BLOB_READ_WRITE_TOKEN`, и новые
обложки пойдут туда. Пока её нет, картинки хранятся в базе — это
рабочий вариант, просто менее правильный при большом количестве работ.

**Остальные три сайта.** `invitation.azim-dev.uz`,
`invitations.azim-dev.uz` и `svarog.azim-dev.uz` пока живут на старом
хостинге. Их переносим отдельно, когда основной сайт устоится.
